# Security and trust boundary

The dossier, clearance level, encrypted-channel wording, credential check, hash, access grant, location warning, and audit trail are **fictional UI**. There is no real identity verification, encryption channel, authentication, authorization, location capture, server submission of a hash, or evidentiary audit record. The session ID is generated in the browser (`crypto.randomUUID()` when available, otherwise `Math.random()`), and event timestamps come from the visitor's device clock. The entries remain in the page DOM for that visit; site code does not transmit or persist them.

Do not turn these displays into claims of actual security controls or legal evidence. If introducing collection, tracking, or real credentials, require an explicit product/security decision first, document storage and retention, and review user-facing disclosures. Never put secrets in Astro client scripts or `public/` assets. `wrangler.jsonc` contains domain and assets configuration, not secrets.

Both pages load Google Fonts externally, and normal site/asset requests still reach the hosting provider. Thus the on-page footer's broad `NO DATA IS COLLECTED OR STORED` is not a verified statement about all network traffic. Distinguish browser-local simulated audit data from external resource requests and hosting logs when updating disclosures. The verify page includes `noindex`, but this is not access control. Browser autoplay is not guaranteed, even though playback starts from a click; preserve the fallback controls. Media rights have not been verified (see [README](../README.md)).
